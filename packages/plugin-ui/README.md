# wings-plugin-ui

React components for [Wings](https://github.com/josippapez/Wings) plugin pages, and the stylesheet Wings draws them
with. The components are Base UI's, like the Wings app's own shadcn/ui ones, with shadcn's names and variants.
Build and pack the plugin with [wings-plugin-sdk](../plugin-sdk/README.md).

```sh
npm install --save-dev wings-plugin-sdk wings-plugin-ui react react-dom @types/react
```

`wings-plugin-ui` lets a page say what it shows and where, and Wings decides how it looks. A page built from
it never touches the DOM, writes HTML or lays itself out with CSS, so when Wings moves or redesigns a place,
your page follows without a release.

```ts
// src/lib/messages.ts
import { channel } from "wings-plugin-sdk/messages";

export const ch = channel<{}, {}, { usage: { key: void; value: { percent: number } } }>();
```

```tsx
// src/pages/usage.tsx
import { useQuery } from "wings-plugin-sdk/react";
import { Card, Gauge, Heading } from "wings-plugin-ui";

import { ch } from "../lib/messages";

export const page = { place: "sidebar" };

export default function Usage() {
  // The `usage` query your main script serves on `ch`: null until main has sent it, then each change.
  const { data: usage } = useQuery(ch, "usage", undefined);
  if (!usage) return null;
  return (
    <>
      <Heading>Usage</Heading>
      <Card>
        <Gauge label="Today" percent={usage.percent} levels={[75, 90]} />
      </Card>
    </>
  );
}
```

## Places

A page in `src/pages/` default-exports its component and exports `page` with the place it shows in, and
`wings-plugin build` writes the mount: it calls `showSidebar`, `showPopover`, `showView`, `showTab`, `showBlock` or
`showSettings` with `<Usage />`. `showBlock` is a view's shell that also keeps a block on a Project page as tall as
the page, by asking Wings for its height with `wings.setHeight` each time it changes. Each mounts a React element in that place's
shell: Wings' padding, spacing and scrolling for a sidebar, a popover, a view (in a modal or a window), a tab or the
settings page. `fill: true` in `page` lays the page out edge to edge with no padding, for a page that scrolls on its
own, like a canvas. The functions are exported too, for a page that mounts itself, with `{ fill: true }` as their
second argument.

You don't write the page's HTML. For `src/pages/sidebar.tsx`, `wings-plugin build` writes `dist/sidebar.html` with
a mount point, its CSS and its script, titled like the manifest's page. A `dist/sidebar.html` you write yourself
wins: the build only writes a page that's missing or that it wrote before (it carries a
`Generated by wings-plugin build` line). A popover's page takes its sidebar's title, the name Wings gives the
popover too. A page that builds its DOM itself, without React, gets the same shell
from `mountShell(place, options)` in `wings-plugin-sdk/shell`, which returns the element to fill.

## Talking to main

A page and your main script talk through a `channel` from `wings-plugin-sdk/messages`. Main serves data with
`serve`, and a page reads it with `useQuery(ch, name, key)` from `wings-plugin-sdk/react`, whose `data` is `null` until
main has sent it. `ask` puts a question to main, and `useBroadcast(listener)` gets every raw `wings.broadcast`
message.

## Page hooks

A page about a project, a tab or a block reads these from `wings-plugin-ui`. Each follows the `wings` object, so a
page doesn't wire up `onProject` or `tabState` itself.

| Hook | Gives |
|---|---|
| `useProject()` | The project the page is about: `undefined` until Wings says, then the project, or `null` when none is open. Follows `wings.onProject` |
| `ProjectGate` | Shows `children(project)` once Wings has said which project, keyed by its id, so a page that holds state starts over for another project. Shows `loading` until then and an `Empty` titled "No project" (or your `empty`) when none is open |
| `useTabState(initial, check)`, `useBlockState(initial, check)` | `[value, set]`: the state saved with `wings.setTabState` or `setBlockState`. `check` turns what was saved, which is any JSON, into the value, or `null` to use `initial`. The value is `null` until it is read. A save that fails leaves the page with the value it set |
| `useViewArgs(check)` | What `wings.openView` opened this tab with, read by `check`, or `null`. Read once: a tab opened with other args reloads |
| `useAction()` | `{ run, busy, error, clear }`. `run(fn)` runs an async action and resolves to whether it worked: `busy` is true while one goes and `error` has the message of the last one that threw, for a button's `busy` and an error `Notice` |
| `usePoll(load, ms)` | Calls `load` on mount and when it changes, if Wings is in front, then every `ms` while it is, and once when Wings is back. Wrap `load` in `useCallback`. For data a query doesn't cover, since a `useQuery` is refetched by main |
| `copyText(text)` | Puts `text` on the clipboard, with a fallback for a frame that refuses the clipboard API |

```tsx
// src/pages/project.tsx
import { Button, Notice, ProjectGate, useAction, useTabState } from "wings-plugin-ui";

export const page = { place: "tab" };

export default function Project() {
  return <ProjectGate>{(project) => <Opened name={project.name} />}</ProjectGate>;
}

function Opened({ name }: { name: string }) {
  // Saved with the tab, and back after a restart. `null` until it is read.
  const [opened, setOpened] = useTabState(0, (raw) => (typeof raw === "number" ? raw : null));
  const { run, busy, error } = useAction();
  const open = () => run(async () => {
    await wings.openUrl("https://example.com");
    setOpened((opened ?? 0) + 1);
  });
  return (
    <>
      {error && <Notice tone="danger">{error}</Notice>}
      <Button busy={busy} onClick={() => void open()}>
        {name}: opened {opened ?? 0} times
      </Button>
    </>
  );
}
```

Memoized on `source` |

Every component passes other props, like `id`, `title`, `className`, `onClick` and `aria-*`, to its element.
`TextInput` and `SearchField` pass `ref` to the input on React 19.

A button that's working on something is `busy`: it shows a spinner, ignores clicks and says so with `aria-busy`
and `aria-disabled`, and unlike `disabled` it keeps the keyboard focus:

```tsx
// src/ui/save-button.tsx
import { Button } from "wings-plugin-ui";

export function SaveButton({ saving, save }: { saving: boolean; save: () => void }) {
  return (
    <Button busy={saving} onClick={save}>
      Save
    </Button>
  );
}
```

## Ours or your own

The components are there for a page that looks like the rest of Wings without effort, not a rule. Write your
own components next to them, and your own CSS: import it from the page, `import "./sidebar.css"`, and the build
bundles it into `sidebar.css` and links it from the generated page. Match Wings with its variables, which every
page has:

| Variable | What |
|---|---|
| `--wings-fg`, `--wings-muted` | Text, and quieter text |
| `--wings-surface`, `--wings-hover`, `--wings-pressed`, `--wings-input` | Card, hovered, pressed and input backgrounds |
| `--wings-hairline`, `--wings-hairline-strong` | Borders |
| `--wings-ring` | The focus ring |
| `--wings-primary`, `--wings-primary-fg` | The primary button, and its text |
| `--wings-info`, `--wings-success`, `--wings-warning`, `--wings-danger` | Tones |
| `--wings-radius` | A card's corners |
| `--wings-menu-bg`, `--wings-menu-ring`, `--wings-menu-active`, `--wings-shadow` | A raised layer like a menu or a list of suggestions, as Wings' own menus draw it: its opaque background, its edge, the highlighted option and its shadow |
| `--wings-font`, `--wings-mono` | Fonts |

The colours, radius and font come from the Wings app's theme (`apps/desktop/src/index.css`), copied into the generated block at the top of `plugin-ui.css` by `pnpm tokens` in `apps/desktop`; edit the theme there, not the block. The file keeps those values, so the package works on its own.

```tsx
// src/pages/sidebar.tsx
import "./sidebar.css";

export function Banner({ children }: { children: string }) {
  return <div className="banner">{children}</div>;
}
```

```css
/* src/pages/sidebar.css */
.banner {
  padding: 8px 10px;
  border-radius: var(--wings-radius);
  background: color-mix(in srgb, var(--wings-info) 14%, transparent);
  color: var(--wings-info);
}
```

Wings' base styles cover plain elements (buttons, inputs, selects and the page's font and colours), the `w-*`
classes and two older helpers, `.muted` and `.card`; nothing else, so your other classes are yours. Your CSS
loads after Wings', so it wins where you style a component, like `.my-list .w-list-button { height: 24px; }`.

## The class contract

The components render plain elements with `w-*` class names and data attributes, like
`<div class="w-card" data-size="compact">`, and no styles of their own. Wings styles them in its
`plugin-ui.css`, which ships with the app, so a Wings update restyles every plugin. The names are a versioned
public contract. `Meter` sets `--w-value`, how full it is, and a `Dot` with a `color` sets `--w-color`; both are data
rather than styles.

`w-shell` with `data-place` (`sidebar`, `popover`, `view`, `tab`, `settings`) and `data-fill`; `w-row`,
`w-stack` with `data-gap`, `data-align`, `data-justify`, `data-wrap`, `data-grow`; `w-text` with `data-tone`,
`data-size`, `data-weight`, `data-mono`, `data-numeric`, `data-truncate`, `data-clamp`, `data-grow`;
`w-page`, `w-page-body` with `data-flush`; `w-toolbar`, `w-toolbar-title`, `w-toolbar-main`, `w-toolbar-actions`; `w-list-detail` with `data-has-detail` and `--w-list-width`, `w-list-detail-list`, `w-list-detail-detail`, `w-list-detail-body`, `w-list-detail-back`; `w-board`, `w-board-column`, `w-board-column-header`, `w-board-column-title`, `w-board-column-count`, `w-board-column-actions`, `w-board-column-body`; `w-split` with `data-direction`, `data-dragging` and `--w-split-size`, `w-split-pane`, `w-split-handle`;
`w-title` with `data-size`; `w-heading`, `w-heading-row`; `w-card` with `data-size`; `w-gauge`, `w-gauge-label`, `w-gauge-value`,
`w-gauge-note`, `w-meter` with `data-tone`, `w-meter-fill`; `w-stats`, `w-stat-label`, `w-stat-value`;
`w-props`, `w-prop`, `w-prop-label`, `w-prop-value`; `w-list` with `data-density`, `w-list-item`,

`w-loading`, `w-empty`, `w-empty-detail`; `w-button` with `data-variant`, `data-size`, `aria-disabled`; `w-chips`, `w-chip`;
`w-tabs` with `data-variant`, `w-tab`; `w-field` with `data-layout`, `w-field-row`, `w-field-label`, `w-field-hint`,
`w-field-group`, `w-input`, `w-search`, `w-select`, `w-check`; `w-combobox`, `w-listbox`, `w-option`,
`w-option-label`, `w-option-detail`, `w-option-empty`; `w-menu-root`, `w-menu` with `data-align`, `w-menu-item`

A `ul` or `ol` with `w-row`, `w-stack` or `w-card` loses its bullets.

## Tailwind or any CSS

Wings' styles sit in CSS cascade layers, declared before anything else on the page, in this order:
`wings-base, theme, base, wings-components, components, utilities`. Any CSS a page brings that isn't in a layer
wins over all of Wings'. Tailwind v4 fits in as it is: `@import "tailwindcss";` puts its reset in `base`, under the
components here, and its utilities in `utilities`, over them. So a page can use Tailwind for its own parts next to
these components, and both look right. Build Tailwind's CSS with its CLI before `wings-plugin build` and import
it from the page. Rem units mean 16px, the browser's root size, while the page's text is 13px.

## Linked packages

With the packages linked from a local folder (`npm link`, or `link:` in `package.json`) rather than installed,
TypeScript looks for React next to their folder. Point it at yours in `tsconfig.json`; the build already
does:

```json
"paths": {
  "react": ["./node_modules/@types/react"],
  "react/*": ["./node_modules/@types/react/*"]
}
```
