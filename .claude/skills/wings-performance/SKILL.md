# Performance in Wings

Wings is a native app drawn with GPUI, around live terminals, and the terminals are the expensive part. Most slowdowns come from resizing terminals, redrawing or calling the network far more often than the screen needs.

## Rules

1. **Nothing heavy per frame.** A sidebar slide or an edge drag changes the pane area's size on every frame. Work that reacts to size waits until the size holds still. `TerminalView::layout` in `apps/native/src/terminal_view/mod.rs` sends the grid and PTY resize 80 ms (`RESIZE_DELAY`) after the bounds stop changing, so a slide resizes the shell once. Never resize a terminal from a drag handler or an animation frame. Let `layout()` pick up the new size.
2. **Commit a drag once it ends.** An edge drag (left sidebar, right sidebar, docked diff) saves nothing until the pointer is released, and then writes the file once (`workspace/sidebar/mod.rs`).
3. **Animate with `motion`, and respect Reduce motion.** Use `motion::tween` and the durations in `apps/native/src/ui/motion.rs`. A tween asks for frames only while it runs. `motion::reduced(cx)` decides what a transition keeps: the sidebar drops its slide and keeps its fade. Spinners share one 30-a-second clock (`ui/status_dot.rs`), so any number of them cost one redraw per step. In a page, spinners, working dots and shimmering text move in the window's layer (`ui::view_spinner_layer`, `ui/shimmer.rs`), so a step redraws the layer and never the page: a page that redrew for its spinners rebuilt the whole chat 30 times a second, about a full core while Claude worked. Never put a repeating `with_animation` in a page. Animated backgrounds draw in a Core Animation layer under the window (`ui/native_backdrop.rs`), so a step draws no window frame. Spinners in slots turn in Core Animation over the window (`ui/native_spinners.rs`, `ui/spinner_host.rs`): a working agent draws no window frame for them. A spinner under an overlay turns in the window instead, so every overlay drawn over the page wraps its root in `ui::cover`. Only the shimmering text still steps the window, 10 times a second.
4. **Hidden things cost nothing.** A hidden pane keeps reading its shell but stops painting. After 10 minutes hidden (`UNLOAD_AFTER`) its scrollback becomes text: 10,000 lines cost about 51 MB as cells and 0.5 MB as text (measured). A hidden window stops making screens. Images that leave the screen drop their textures (`window.drop_image`). Put parts that rarely change in a `.cached(...)` piece (`workspace/parts.rs`), so a terminal's output doesn't rebuild the sidebar.
5. **Poll slowly, and only while it matters.** Local checks every 15 s or slower, network every 60 s or slower, and only while Wings is in front (`window_active`), like the git sweep in `workspace/sidebar/git.rs` and the usage poll in `crates/wings-connect/src/usage.rs`. Prefer an event to a poll, as the git sweep follows `wings-gitwatch`. After a 429 or a server error, back off, and wait for `Retry-After` when the answer has one. A plugin polls with `poll::while_focused` from the Rust plugin SDK (`packages/plugin-rs/src/poll.rs`). Offer a Refresh button rather than polling faster. Cache network lookups per repo and branch, not per pane.
6. **Notify only what changed, and never the workspace for a step.** GPUI redraws a notified view and every view above it, and each of the workspace's pieces (`workspace/parts.rs`) observes the workspace, so `cx.notify()` on the workspace rebuilds and lays out the sidebar, title bar and main column. Anything that steps on a timer draws in a view of its own: the spinner layers are `ui::SpinnerLayer` views, so a step redraws them alone. Before notifying for a plugin event, poll result or setting, check that the value changed: plugins send the same badge, status and section rows again on every poll (`apply_plugin_event`). A page anywhere, the tab's or the right panel's, says it is on screen (`ui::place_view`) after the workspace's draw starts (`ui::start_draw`), so its spinners turn in the layer. A slow ambient motion (the empty chat's glow) steps at 10 a second, not the spinners' 30.
7. **A click never waits.** Open the view in a loading state, then fill it. Process scans, keychain reads, HTTP and git run on `cx.background_executor()`, never on the UI thread.

## Measure before and after

State a number for the change, not "feels faster". Run from the repo root. The examples need `--features test-support` and draw offscreen with real Metal, so they run on macOS only. Use `--release` for timings.

- **Frame cost while an agent works:** `cargo run --release --manifest-path apps/native/Cargo.toml --example bench_redraw --features test-support`. It prints median, mean and p90 ms per frame for an idle redraw, the spinner alone, one changed row, a full-screen scroll and a split tab. `BENCH_SCREEN=<file>` replays a recorded screen instead.
- **A gesture that changes the pane area:** the tests that check a slide or drag resizes the shell once also print a `[measure]` line with frames and ms per frame: `cargo test --manifest-path apps/native/Cargo.toml --features test-support --lib once_when_it_settles -- --nocapture`. A new gesture gets the same test.
- **Diff scrolling:** `--example bench_diff_scroll`. **Plugins:** `--example bench_plugins` gives each plugin's memory and time to its first screen.
- **Terminal replay:** `cargo test --release --manifest-path apps/native/Cargo.toml --features test-support --lib -- --ignored --nocapture bench_replay` draws a full ring of recorded Claude Code output (`apps/native/bench/claude-fullscreen.rec`).
- **Polling:** count the calls with a fake in a test, as the tests in `apps/native/src/workspace/usage.rs` do, and check that nothing is asked while Wings is behind other apps.

## Find what keeps the running app busy

When Wings uses CPU with nothing happening, find who asks for the frames before changing code. Measured this way, an idle 0.2.61 used 35% of a core, all of it from a spinner step rebuilding the window's pieces.

1. **Measure idle for real.** A Claude session running in Wings (this one too) is not idle: its own turn draws. Run the measurement in the background with a delay, end your turn, and read it when it finishes: `sleep 20; P=$(pgrep -f MacOS/wings-native); top -l 21 -s 1 -stats pid,cpu -pid $P | grep "^$P" | tail -20` (average the second column), then `sample $P 5 -file /tmp/wings.sample`. Ask the user to leave Wings alone for that minute.
2. **Read the sample's main thread.** Time under `display_timer_callback` → `Window::draw` is frames. Deep `prepaint`/`compute_layout` under a `Part` means a piece of the workspace is rebuilt, not reused from its cache; `Part::render` and `PageView::render` say which. Rust symbols in a sample are mangled: the identifiers are the length-prefixed words in them.
3. **Ask the running app who notifies.** `sh .claude/skills/wings-performance/scripts/who-redraws.sh 6` attaches lldb for 6 seconds, records the stack of every `App::notify` and `invalidate_view`, detaches, and prints the callers per second. `invoke_observer … Part::new` means the workspace was notified and all its pieces rebuilt; look at what notified it. lldb pauses Wings a few ms per hit; the script always detaches (check `ps -o stat= -p <pid>` has no `X`).
4. **Fix the cause, with a test that counts draws.** Count a view's renders across clock steps (`TestApp::advance_clock`), as `a_spinner_step_leaves_alone_a_piece_that_follows_the_window` (`ui/status_dot.rs`), `a_spinner_in_a_right_panel_page_turns_without_drawing_the_page_again` and `a_badge_sent_again_unchanged_draws_nothing_again` do. Check it fails on the old code. A test view that doesn't observe its root, as the workspace's pieces do, misses the most expensive case.
5. **Measure again in the installed app** after the release, the same way as step 1, and say both numbers.

Don't click through the GUI while the user is using their Mac. Use the offscreen examples and `examples/shot.rs` instead.
