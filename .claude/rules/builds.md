# Builds

Build and run tests through the queue, from the main checkout: `sh scripts/build.sh <command>`, for example `sh scripts/build.sh cargo test --manifest-path apps/native/Cargo.toml --features test-support --lib <filter>` or `sh scripts/build.sh sh plugins/build-rust.sh claude-chat`. It runs up to two builds at once in the checkout's own target folders (`apps/native/target`, `plugins/target`), a third waits for one of them, and it drops the incremental caches when under 8 GB is free and no other build is running. After each command, when no other build is running, it deletes the object files no binary links any more (`scripts/prune-objects.py`): macOS debug builds keep them and piled up 23 GB in a day. Cargo itself makes two builds in the same folder take turns compiling, then their tests or screenshots run side by side. Every other place that built made a target folder of several GB of its own, and the disk filled up.

- Subagents build and test their own code through it: compile, run the tests they wrote, and hand back working code. A hook refuses a subagent's `cargo build|test|run|check|clippy`, `build-rust.sh`, `package-mac-app.sh` and `pnpm shot|test|build` outside `scripts/build.sh`.
- Another agent may be editing the same checkout: a compile error in a file you didn't touch is theirs, so say so instead of fixing it.
- Never set `CARGO_TARGET_DIR`, and don't build in a worktree (the script refuses).
- Change `scripts/build.sh` by writing the new version to another file and moving it over: a build running it reads it as it goes, and an edit in place can make it run its command twice.
