# Builds

Build and run tests through the queue, from the main checkout: `sh scripts/build.sh <command>`, for example `sh scripts/build.sh cargo test --manifest-path apps/native/Cargo.toml --features test-support --lib <filter>` or `sh scripts/build.sh sh plugins/build-rust.sh claude-chat`. It runs up to two builds at once in the checkout's own target folders (`apps/native/target`, `plugins/target`), a third waits for one of them, and after each command it removes the build output nothing uses any more (`scripts/prune-builds.py`): this repo's crates' builds untouched for six hours but each one's newest (every version bump and dependency change leaves the app's old builds behind, 30 GB in a day), old incremental caches, and, when no other build is running, the object files no binary links (macOS debug builds keep them: 23 GB in a day). Under 8 GB free it does that first, and only if that isn't enough and no other build is running it drops the incremental caches, which makes a one-line change of the app compile in 55 s instead of 16 s. Cargo itself makes two builds in the same folder take turns compiling, then their tests or screenshots run side by side. Every other place that built made a target folder of several GB of its own, and the disk filled up.

- Subagents build and test their own code through it: compile, run the tests they wrote, and hand back working code. A hook refuses a subagent's `cargo build|test|run|check|clippy`, `build-rust.sh`, `package-mac-app.sh` and `pnpm shot|test|build` outside `scripts/build.sh`.
- Another agent may be editing the same checkout: a compile error in a file you didn't touch is theirs, so say so instead of fixing it.
- Never set `CARGO_TARGET_DIR`, and don't build in a worktree (the script refuses).
- To try a plugin change or take its screenshots, build it with `sh scripts/build.sh sh plugins/build-rust.sh --quick <plugin>`: a few seconds instead of a minute or more. Its modules are bigger and slower, so build it again without `--quick` before you commit. A hook refuses a commit with a quick module in it.
- Change `scripts/build.sh` or `plugins/build-rust.sh` by writing the new version to another file and moving it over: a build running it reads it as it goes, and an edit in place can make it run its command twice.
